# Handoff (for a fresh agent)

**Project:** Tomato, a statically typed, reference-counted language with indentation syntax, compiled through LLVM. Owner: Davis McDowell (`davis@fc.run`). He decides all language semantics; his messages are short and typo-ridden, so state your reading back and flag uncertain ones "reading to confirm". Where syntax is undecided use a placeholder and log it in `docs/provisional.md`.

**State (repo `sirbuffalo/tomato`, public; the version is in `VERSION`):**
- The compiler written in Tomato (`compiler/src`) is the **only** implementation; it compiles itself (fixed point). `compiler/bootstrap/tomatoc.ll` is its own IR (regenerate with `compiler/bootstrap/refresh.sh`). Do not add Python.
- `runtime/` is the C runtime, `std/` the standard library, `native/` the `tomato` command and repl (shell), `site/` the website (tomato.davismcd.com, GitHub Pages; compiles and runs in the browser with WebAssembly: `site/wasm`, an LLVM IR interpreter in `site/wasm/llvm.js`), `editors/vscode` the grammar, `release/build.sh` builds release archives, `tests/run.sh` is the whole test suite (clang only; jsc on macOS or node elsewhere (through `native/jsc-on-node.js`) for the wasm path, expect for the repl history check), `tests/known_gaps/` is where a program per decided rule not built yet goes.
- Releases are GitHub releases `vN` with `tomato-N.tar.gz` and `latest.json`; `tomato update` reads it. The status table in `docs/specification.md` is authoritative about what is built.

**How to work here:**
- Run `tests/run.sh` (set `WASI_SDK` to a WASI SDK 24 folder to also rebuild the wasm files and compare them byte for byte, on macOS or Linux). A test program that writes files takes the folder as `def main(dir: str = '/tmp')` and `tests/run.sh` passes its own `mktemp -d` (removed at the end), so users and parallel runs never share a fixed `/tmp/tomato_*` name; paths that must not exist use `/nonexistent_dir_for_tomato/`, and error text that names the folder is shown as `<dir>` (see `json_files`, `toml_api`, `msgpack_files`). After changing `compiler/src`, run `sh compiler/bootstrap/refresh.sh`; after changing the compiler or runtime, rebuild `site/wasm` with `site/wasm/build.sh` (WASI SDK 24 on any host: Linux and macOS builds are byte-identical, see docs/releasing.md, The wasm files); bump `VERSION` and `site/config.js` together, run `release/build.sh`, then `release/pkg.sh`, and `sh site/build.sh`; upload `tomato-N.pkg` with the release.
- Git: commit with byre's snapshot tool; **never push this branch's history** (two old commit subjects mention chat passwords). Push one squashed commit onto `origin/main`: `git fetch origin; T=$(git write-tree); C=$(git commit-tree $T -p origin/main -m "..."); git push origin ${C}:refs/heads/main`, then `gh release create vN release/out/tomato-N.pkg release/out/tomato-N.tar.gz release/out/latest.json`.

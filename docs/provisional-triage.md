# Triage of `docs/provisional.md` for the 1.0 promise

Date: 2026-11-27 (D109a). Written by the agent for Davis's review. Updated the same day for the answers recorded in D116a (judgments 2, 3 and 4 below), D117a (judgment 1) and D126a (judgments 5 to 11 and 13, answered by Davis later on 2026-11-27; judgment 12 is still open). Davis's principle for the answers: freeze less rather than more. The task was the one the language design review asks for in 1.1: give each of the 91 rows one of three outcomes, so that the promise can say "all 1.0.x releases are compatible, except the N features on the unstable list".

| Outcome | Rows | What it means |
| --- | --- | --- |
| Promoted to decided | **61** | part of the promise; the last column of `provisional.md` section 2 cites the decision or the test that pins it |
| Kept on the unstable list | **4** (+2) | outside the promise (`provisional.md`, section 1; `releasing.md`, Compatibility says "6 features"). Four are rows (P20, P84, P68, P91); D126a added two features that are carved out of promoted rows, the marker names beyond `@add` (U5, from P23 and P65) and the order async tasks run in (U6, from P85), so the 91 rows still add up |
| Removed as superseded | **26** | gone from the promise; section 3 says why and where the behaviour is decided now |

Every promoted row was compared with the current compiler: a small program for each non-trivial row, run with the `tomato` built from `main` on 2026-11-27, or a test that already pins the behaviour. Where the old text no longer matched, the row was **not** promoted as written: its text was corrected (promoted rows below), or the row was removed (P15, P16, P18) or put on the list (P44). `main` moved while this was written (`x is T`, D23i; builtin shadowing, D108a; the release-mode error line, D34c); the rows were re-checked against those changes (P31, P44 and P88 changed).

## Judgment calls for Davis, one by one

Each had my recommendation; Davis's answers, where given, are marked **Answered**.

1. **The error promise (ADOPTED as proposed by Davis, 2026-11-27, D117a).** `docs/releasing.md` now says: an error id never changes its meaning; the class an operation raises does not change within a minor version; message text may be reworded in a patch release but the first line keeps its id; and a decided rule the compiler does not enforce yet is enforced only in a minor release. Because of the third point, "error message wording" (P20) is on the unstable list as U1. *Recommendation: yes.* If you say no to the wording rule, remove U1 and the promise becomes 6 features, with every message word promised for ever (which I would not do: messages are still being improved).
2. **`!name` foreign functions (P33). Answered by Davis, 2026-11-27, and built (D112a).** `!name` stays open for any symbol except the runtime-private `tomato_*` functions, which are reserved outside `std/` (E611, E612 for seeds). It is no longer on the unstable list. Review 1.6's `std/`-only and opt-in proposals are not adopted.
3. **The edges of the type test (P44). Resolved (D23i, D110a; D116a).** `x is T` is the spelling, `x is Class` checks the object's own class (built, D110a), and the old `x in T` spelling stays a warning through 1.0.x; making it an error or silent is a minor-release change (D23i rule 5). P44 is promoted and off the unstable list.
4. **Entry markers other than `@main` (P21). Answered by Davis, 2026-11-27, and built (D113a).** `@name` stays the spelling (review 2.1's `@entry name` is not adopted), markers may be dotted (D96a), and a published list of reserved marker names may not be used as an entry point (E613). It is no longer on the unstable list.
5. **The host input protocol (U2, P84). Answered (Davis, 2026-11-27, D126a): keep listed, and it may change in any 1.x release.** `TOMATO_INPUT_ASK=1`, exit code 75 and the echo of answers are the implementer's design; the repl and the website depend on them. Listed. *Recommendation: keep listed (it costs one line), and promote it when the repl or an embedder needs it stable.*
6. **`progress_bar`'s drawing (U3, P68) and `random.choice`/`shuffle`/`sample` (U4, P91). Answered (Davis, 2026-11-27, D126a): keep both listed; "any thing can change in a 1.x", with no deprecation first.** Both are listed: the bar will probably gain speed and time left; the random helpers want to become methods once generic methods exist. *Recommendation: keep both listed; they are the cheapest honest exceptions.*
7. **Marker names (P23, P65). Answered (Davis, 2026-11-27, D126a): not frozen, so against my recommendation: the names beyond `@add` are on the unstable list as U5.** I promoted the operator and protocol markers (`@sub @mul @div @floordiv @mod @pow @eq @lt @le @gt @ge @bitand @bitor @bitxor @invert @neg @rmul @hash @set`, and `@len @get @slice @contains @reversed @iter` of D48a). D12k decided the mechanism and the review (2.1) keeps it, but the names beyond `@add` were chosen by the implementer. *Recommendation: promote (changing a marker name later breaks every class that uses it).*
8. **The order tasks run in (P85). Answered (Davis, 2026-11-27, D126a): not frozen, so against my recommendation: the order is on the unstable list as U6.** D51a-c and D58a-e decided async; the order tasks run in, the frame layout and the end-of-program rule were the implementer's design, and a dozen tests (`tests/programs/async_*.tom`) pin the order. Promoted. *Recommendation: promote; the unbuilt parts (two tasks reading the same statuses, timeouts, `t.cancelled()`) only add.*
9. **Promoted rows that no decision number of yours backs. Answered (Davis, 2026-11-27, D126a): frozen for P7, P8, P14 and P17; not frozen for the number-theory edge cases P67, P70, P71, P73, P77, P78 and P79** (a minor release may change them, with a Breaking changes entry; they are not on the unstable list, so a patch release does not). They are the behaviour of every release, checked and tested, but nobody decided them: **P7** (a block starts no new scope; only functions do), **P8** (conditions must be `bool`: no truthiness), **P14** (redeclaring a name with the same type in a function is accepted, another type is E292), **P17** (a subclass may not redeclare a field), and the edge choices of the number-theory helpers **P67, P70, P71, P73, P77, P78, P79** (`prev_prime(2)` raises E42, `nth_prime(0)` E43, `totient(0)` is 0, `is_coprime(0, 0)` is False, `lcm(0, x)` is 0, `is_prime` is a probabilistic test from 3.3 * 10^24 up). *Recommendation: promote all of them. P7 and P8 are the two that shape the language; P7 is Python's function scope and P8 the strictness of Go and Rust *(general knowledge)*; changing either later breaks programs.*
10. **Decided rules the compiler does not enforce or build (P15, P16, and the other gaps in the specification's "Not yet" cells). Answered (Davis, 2026-11-27, D126a): yes, as recommended; they stay out of the promise and a minor release may enforce them.** I removed rows P15 (class conversion `Circle(s)`, D12az and D12bh: the compiler rejects it with E128 or E324) and P16 (`@init` flow analysis, D12x: the compiler accepts a field left unset) instead of promoting text that does not match. Making the compiler enforce a rule it ignores can reject a program that works today, so the fourth bullet of the proposed error promise puts it in a minor release. Adding a feature that is an error today (class conversion) only adds. *Recommendation: yes; follow-up below: record P15 in `tests/known_gaps`.*
11. **Implementation-note rows removed without a replacement (P36, P39, P40, P41, P42, P52, P53). Answered (Davis, 2026-11-27, D126a): yes, as recommended; the debug leak report and `TOMATO_GC_STATS` are diagnostics outside the promise.** Two of them describe something a person can see: the debug-mode report of objects never freed at exit (D29c, P39) and `TOMATO_GC_STATS=1` (P42). I treated both as diagnostics outside the promise rather than listing them. *Recommendation: yes. If you want the leak report promised, it needs its own decision.*
12. **Review items that block 1.0 and are not rows of this file (not answered yet).** If any is still open at 1.0, it must be added to the unstable list, because it would otherwise be a promise nobody decided (1.3, 1.4, 2.2, 9.1 and the std names of 2.3 and 10 are decided and built since: D34c, D108a, D23i, D115a, D122a): `File` safety (5.1, built as a default by D93a), the sleep clock (6.1), D77g's limits (7.1), `bytes` (8.1) and `tomato run` inputs (11.1). *Recommendation: decide them before 1.0 in the review's ranked order; this triage lists none of them as unstable because that would be a guess.*
13. **The Unicode version (review 1.5). Answered (Davis, 2026-11-27, D126a): yes, as recommended; no Unicode promise, and the changelog names the Unicode version in the release that changes it.** Not written into the promise: the tables follow Unicode 16.0, and a new Unicode version changes `isalpha`, `isdigit`, case mapping and widths. Since a minor release may change behaviour and lists it, that is already allowed. *Recommendation: say nothing more, but name the Unicode version in the changelog of the release that changes it.*

Not a question: **a compiler warning** when a program uses an unstable feature (review 1.1's suggestion) is built (D121a): kind `unstable`, once for each feature in a build, for U3 and U4 (U1 and U2 are not written in a program); `# allow: unstable` or `--no-warnings` hides it. It was first left as a follow-up because it needed a bootstrap IR refresh and a wasm rebuild.

**Still open for Davis after D126a:** judgment 12 (the review's other 1.0 blockers). Judgments 5 to 11 and 13 were answered on 2026-11-27 (D126a), after D116a had answered 2 to 4. Judgment 1 (the error promise) was answered yes on 2026-11-27 (D117a); U1 error message wording stays on the list as the promise says. Of the review's other blockers, the error class tree (4.1, D114a) and reserved std module names with `import ... as` (9.1, D115a) are built on `main`; `bytes` (8.1) is not decided in `decisions.md`, so this file does not count it.

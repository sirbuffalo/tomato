# Provisional choices

This file began as the list of places where the language had no decision and an implementation made a guess. On 2026-11-27 every one of its 91 rows was triaged once, before 1.0 (D109a; the outcome, and Davis's answers of the same day, are in [`provisional-triage.md`](provisional-triage.md); D126a). Each row now has exactly one outcome:

1. **6 rows stay provisional** and are the *unstable list* (section 1): features Davis may still change (his words: any of them can change in a 1.x). Four of them are rows of the old table (P20, P84, P68, P91); U5 and U6 are carved out of rows P23, P65 and P85, which stay promoted for everything else. The 1.x compatibility promise (`docs/releasing.md`, Compatibility) does not cover them, and nothing else in this file is an exception to it.
2. **61 rows are promoted to decided** (section 2): the behaviour has been stable for many releases, was checked against the current compiler on 2026-11-27, and the last column names the decision or the test that pins it. They are part of the promise: the language rules are frozen in 1.x, the std rows follow the deprecation rule, and the edge cases of seven number-theory rows are not promised (the head of section 2 says which).
3. **26 rows are removed** (section 3): superseded by a decision, a later row or the specification, describing the retired Python prototype or an implementation detail, or no longer matching the compiler. Their old text is in git history before D109a.

A new placeholder may be added to this file only on the unstable list. Row numbers (`P23`) are kept because decisions and the specification cite them.

## 1. The unstable list (outside the 1.x promise)

**6 features.** A program that uses one of them may behave differently, or stop compiling, in any later release, a patch release included, with no deprecation or earlier warning first (the deprecation rule of `docs/releasing.md` is for what is promised, not for this list); the changelog lists every such change (under Breaking changes when a program stops working). The compiler warns when a program uses one that program text can show (U3 and U4 today): `warning: 'progress_bar' is an unstable feature (U3, the text progress_bar draws)`, once for each feature in a build, silenced by `# allow: unstable` on the line or by `--no-warnings` (D121a; `docs/errors.md`). U1 and U2 are not written in a program, so they have no warning. U5 (a marker name is written in a program) and U6 (a program that starts a task) could have one, but the compiler does not warn for them yet (`TODO.md`: "Warn for the marker-name and async-order unstable features"). The list is kept in `compiler/src/unstable.tom`, which holds U1 to U4 for now: U5 and U6 are added there when their warning is built. `tests/run.sh` checks that the file and this table list the same features, apart from U5 and U6 (the variable `pending_unstable` in `t_unstable_features`, to be emptied by that item).

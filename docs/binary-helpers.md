# Binary helpers

Binary data is a `list[int]`, with one integer from 0 to 255 per byte. All of these modules work in native programs and the browser. Invalid byte values raise `ValueError`.

`utf8.encode(text)` returns the bytes of a string, preserving any invalid bytes already present in it. `utf8.decode(data, errors='strict')` decodes UTF-8; `'strict'` rejects malformed input and `'replace'` inserts U+FFFD as Python does. Other error modes are rejected.

`hashlib.sha256`, `sha224`, `sha1`, `md5` and `new(name, data=[])` create a `Hash`. `update(data)` or `update_text(text)` adds data. `digest()`, `hexdigest()` and `copy()` do not change the original, so updates can continue afterward. The object exposes `name`, `digest_size` and `block_size`. The `sha256_hex`, `sha1_hex` and `md5_hex` functions are one-shot shortcuts. `pbkdf2_hmac(name, password, salt, iterations, dklen=0)` derives bytes; zero length selects the digest size. SHA-1 and MD5 are weak for collision resistance and should not be used in new security designs.

`hmac.HMAC(key, digestmod)` supports `update`, `digest`, `hexdigest` and `copy`; `hmac.digest` and `hmac.hexdigest` are one-shot equivalents. The digest name is a string such as `'sha256'`. `hmac.compare_digest(a, b)` avoids stopping at the first differing byte, but Tomato does not guarantee that its operations are constant time.

`zlib.crc32(data, value=0)` and `zlib.adler32(data, value=1)` return unsigned 32-bit checksums. Feed the previous result as `value` to continue across chunks. Compression is not yet included.

`struct.pack_ints(fmt, values)`, `unpack_ints(fmt, data)` and `calcsize(fmt)` use standard integer sizes with no alignment: `<` is little endian, `>` and `!` big endian, and `=` and `@` little endian. Codes are `x`, `b`, `B`, `h`, `H`, `i`, `I`, `l`, `L`, `q` and `Q`; a decimal repeat count precedes a code (a count above 1,000,000, or more than 1,000,000 codes in all, raises `StructError`). Unpacking requires exactly the format's size. Format and length errors raise `StructError` (a `ValueError`); numbers outside the code's range raise `OverflowError`. `int_to_bytes(value, length, byteorder='big', signed=False)` and `int_from_bytes(data, byteorder='big', signed=False)` support arbitrary-size integers.

`struct.Packer(byteorder='>')` writes mixed records with `u8`, `u16`, `u32`, `u64`, `i8`, `i16`, `i32`, `i64`, `f32`, `f64`, `raw` and UTF-8 `text`; `bytes()` returns a copy. `struct.Reader(data, byteorder='>')` supplies matching `read_` methods (including `read_f32` and `read_f64`), `read_raw(n)`, `read_text(n)`, `remaining()` and `pos`. A failed read leaves the position unchanged.

`f32` and `f64` write IEEE 754 binary32 and binary64 in the byte order given to `Packer`; `read_f32` and `read_f64` decode them. Tomato floats are always finite (D41a), so a NaN or infinity pattern read from bytes raises `ValueError` and leaves the position unchanged, and `f32` and `f64` raise `OverflowError` for a finite value that rounds beyond the largest binary32 or binary64 (floats have any exponent, so this includes values such as `1e1000000000`, which are refused at once). A value below half the smallest subnormal of the format packs as a signed zero, as in Python. Negative zero and finite subnormal values are preserved; `f32` rounds to nearest, ties to even, as Python's `struct`. NaN payloads cannot be represented by a Tomato `float`. A decoded value is the exact number the bytes name. Tomato floats carry a 53-bit significand at any exponent, so for a binary64 subnormal such as the bytes of 2^-1074 the result is `4.9406564584124654e-324`, which is not equal to the decimal literal `5e-324` (a literal keeps its own 53 bits), although packing the literal gives the same bytes; the same holds for `1e-310`, which comes back as `9.99999999999997e-311`.

# Regular expressions

`import re` provides a Python-style regular expression subset in both native and browser programs. Compile a pattern once when using it more than once: module functions compile on every call and there is no hidden cache.

```tomato
import re

@main
def main():
    p = re.compile('(?P<word>\\w+)', re.I)
    m = p.search('Tomato 42')
    if m is not None:
        print(m.group('word'), m.span())
    print(p.findall('one two'))
```

`compile(pattern, flags=0)` returns a `Pattern`. The module also offers `match`, `search`, `fullmatch`, `findall`, `findall_groups`, `finditer`, `sub`, `sub_with`, `subn`, `split` and `escape`. Their first argument is the pattern; `flags` is their final optional argument. A `Pattern` offers the same operations without the pattern or flags arguments. Its `match`, `search` and `fullmatch` accept `pos=0, endpos=-1`, where -1 uses the end of the text. Positions count characters. `match` starts at `pos`, `search` scans from it, and `fullmatch` must consume through `endpos`.

`match`, `search` and `fullmatch` return `Match | None`. A match has `string`, `pos`, `endpos` and `re` fields. `group(key=0)`, `start(key=0)`, `end(key=0)`, `span(key=0)` and `matched(key=0)` accept an integer or a group name. An unmatched group returns `''` from `group`, `False` from `matched`, and -1 for its positions; a nonexistent group raises `IndexError`. `groups()` returns a list of capture texts, `groupdict()` maps names to texts, and `expand(template)` applies replacement-template rules. `findall` returns whole matches as `list[str]` regardless of group count; `findall_groups` returns `list[list[str]]`; `finditer` eagerly returns `list[Match]`. `split` includes captures, using empty text for an unmatched group.

`sub(pattern, repl, text, count=0, flags=0)` replaces matches; `subn` also returns the number replaced. Templates understand `\1` through `\99`, `\g<1>`, `\g<name>`, `\g<0>`, `\n`, `\t`, `\r`, `\a`, `\b`, `\f`, `\v`, octal escapes (`\0`, `\012`, `\101`, at most `\377`, as in Python) and `\\`; invalid references and unknown letter escapes raise `RegexError`, even when there is no match. `sub_with` takes a named `fn(Match) -> str` in place of the template. Function values do not capture local variables. A count or maxsplit of zero means unlimited.

Flags have Python's values: `IGNORECASE`/`I` = 2, `MULTILINE`/`M` = 8, `DOTALL`/`S` = 16, `VERBOSE`/`X` = 64 and `ASCII`/`A` = 256; combine them with `|`. Other bits raise `ValueError`. `Pattern` exposes `pattern`, `flags`, `groups`, `groupindex` and `step_limit`. A call that exceeds the default 20,000,000 matcher steps raises `RegexError('too many steps (catastrophic backtracking?)')`; assign a different `step_limit` to the pattern when appropriate. One budget is shared by a whole `findall`, `finditer`, `sub` or `split` call, and it grows with the text: the limit is `step_limit` plus 16 steps for each character of the text, so a plain linear scan over a long text (a few steps per start position) does not use it up and only backtracking beyond that allowance does. Each matcher instruction counts one step, a backreference counts the characters it compares (it stops at the first difference), and a choice point counts one more step for every eight capture slots it saves, so the limit bounds matching work and not just the number of instructions. It does not bound pattern compilation or memory: the saved choices of a long match can hold memory in proportion to the number of live choices times the number of groups. Groups (including lookarounds) may nest at most 1,000 deep; a deeper pattern raises `RegexError('pattern is nested too deeply')` (E491) instead of overflowing the stack. Other compile-time limits, each a `RegexError` instead of an out-of-memory failure or stack overflow: a counted repeat `{m,n}` may not exceed 65,535 (E490), because counted repeats are unrolled into the program; the compiled program may hold at most 500,000 instructions (E491), so nested counts such as `(?:a{1000}){1000}` are refused; and one sequence or alternation may have at most 10,000 items or alternatives (E491). `match`, `search` and `fullmatch` keep the converted text of their last call, so a loop that advances `pos` over one text converts it once; the pattern holds that text until it sees another. Each call still compares its text with the kept one, which takes time proportional to the text's length (far less than converting it), so a loop of `search(text, pos)` that makes hundreds of thousands of matches over one long text is quadratic: scan with `finditer`, `findall` or `sub` instead, which are linear.

The syntax includes literals and character escapes, `.`, ranges and negated character classes, `\d \D \w \W \s \S`, `^ $ \A \Z \b \B`, captures, `(?:...)`, `(?P<name>...)`, numbered and named backreferences, `|`, greedy and lazy `* + ? {m} {m,} {,n} {m,n}`, lookahead, fixed-width lookbehind, comments, global flags at the start, scoped flags, verbose mode, and octal escapes (`\0`, `\012` and three-digit `\101` as in Python, at most `\377`; in a class `\1` to `\7` start an octal escape too, so `[\1]` is the character U+0001, while outside a class `\1` to `\99` are group references unless three octal digits make an escape). `$` matches before a final newline as well as at the end. As in Python, a quantifier cannot follow `^`, `$`, `\A`, `\Z`, `\b` or `\B` (`nothing to repeat`), though a group or lookaround around one may be repeated. Possessive quantifiers, atomic groups, conditionals, `\G`, Unicode property classes, `(?L)`/`(?u)` and `\N{name}` are rejected, not ignored. `RegexError.pos` gives the position associated with a bad pattern or template.

One known difference from Python: a counted repeat `{m,n}` around a group that can match the empty string can give different results, because counted repeats are unrolled into optional copies instead of stopping after an empty iteration. The recorded span of that group can differ, and in rare cases so can the overall match span and with it `findall`, `split` and `sub`. For example `(a??){,2}` fullmatch on `'a'` gives group 1 as (0, 1) here and (1, 1) in Python, `(a*?){,2}` on `'aa'` gives (0, 2) here and (1, 2) in Python, `(a??){,3}` on `'aa'` gives (1, 2) here and (2, 2) in Python, and `(.|(\s{,2})??){,2}` with `finditer` on `'\na'` gives the overall spans (0, 0), (0, 1), (1, 2), (2, 2) here and (0, 0), (0, 2), (2, 2) in Python. `*` and `+` repeats agree with Python. Unicode matching uses Tomato's character and simple case-mapping tables. `\s` is the set Python's `str.isspace()` accepts (including `\v`, `\f`, U+0085, U+00A0 and the other Unicode spaces) unless the ASCII flag limits it to space and tab to carriage return. Consequently `\d` includes some digits outside Python's decimal category, and `\w` excludes some numeric characters Python includes. Case matching is one character to one character: it does not make `ß` match `SS`. The ASCII flag restricts the shorthands and case mapping to ASCII. The language's case and category tables define the exact Unicode version.

On this Linux x86-64 development host, an `-O1` native build of the 1,368-row corpus runner took 0.26 s, including reading JSON and comparing results; a Python 3.14 oracle pass over the same rows took 0.16 s. These small-case, one-run measurements include the two languages' different JSON and test harness costs and are not a general speed ratio. In a separate `-O2` run, the default limit on `(a+)+$` against 30 `a`s followed by `b` took about 1.7 s on the same host; the 200,000-character `.*` and 1 MB search checks completed in the same run. `findall`, `sub` and `split` over a long text with very many matches are linear in the text, which `re_limits` checks with 100,000 matches in 200,000 characters. Machine load affects these timings.

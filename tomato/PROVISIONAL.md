# Provisional choices in the Python prototype

The interpreter in this folder implements only decided rules (D-numbers in `docs/specification.md`). Where the language has no decision yet, it uses a Python-like placeholder listed here. **None of these are decisions.** Davis decides each; the prototype changes to match. Constructs that would need a real rule stop with `not yet decided: ...` instead.

Run a program: `bin/tomato run examples/primes.tom` (runs `@main`; `bin/tomato run FILE ENTRY INPUTS...` runs `@ENTRY` with those inputs, D28a; add `--llvm file.ll` to let `!x` run LLVM, which needs `pip install llvmlite`). Compile to LLVM IR: `bin/tomato compile FILE -o OUT.ll`; build a native program: `bin/tomato build FILE -o OUT` (P36); write an interpreter bundle: `bin/tomato bundle FILE -o OUT` (P35); decode an error code: `bin/tomato explain CODE FILE` (P37). Install for the current user: `./install.sh`. Run the tests: `python3 -m unittest tests.test_tomato`.

## Placeholders in use

| # | Placeholder | Why it is needed |
| --- | --- | --- |
| P1 | Indentation blocks, `#` comments, spaces only | R04 says Python-like; layout rules are open |
| P2 | Omitting `-> R` means the function returns nothing (the form itself is D19a) | the no-value spelling is undecided |
| P3 | (settled by D19b: `class Name(Parent) implements A, B:`) | |
| P4 | `interface Name(Parent1, Parent2):` with method signatures that have no colon or body | D12bc decided inheritance, not the spelling |
| P5 | `if` / `elif` / `else` / `while`, `break`, `continue`, `return`, `pass` (`for name in x:` is D18a; the keywords exist per D25a) | the exact forms are undecided |
| P6 | `x = value` infers a local's type from its first value; `x: T = value` declares it | D04b says infer where possible |
| P7 | A block does not start a new scope; function bodies do | scope rules are undecided |
| P8 | `and`, `or`, `not`, `True`, `False`, bool conditions only | operators and bool are undecided |
| P9 | `%` result type for fixed-width integers follows the D05s common-type rule; the sign rule itself is D05au | D05au settles the remainder, not the result type |
| P10 | Comparison operators `== != < <= > >=` on integers by value, floats, strings, bools (== only for others) | undecided |
| P11 | Strings: `'` or `"` (D17a), UTF-8 text counted in characters (D17b-c). Escapes `\n \t \r \0 \\ \' \"` and `\u{hex}`; no multi-line literals, no interpolation | escapes and literal forms are undecided |
| P12 | `print(a, b)` builtin, values separated by a space; floats print the way Python prints them | I/O is undecided |
| P13 | Decimal integer literals only; no float literals | float literal syntax is undecided |
| P14 | Declaring a name twice, or assigning a module variable from a function, stops as not decided | scope rules |
| P15 | `Dog(x)` where `x` is an instance of any ancestor or descendant class is a conversion, decided by the object's real class; it fails with a catchable error otherwise. Interface-typed values are not tracked separately, so this also converts a value held as an interface (D12bh) | D12az and D12bh settle the conversions; the failure's form is open |
| P16 | "`@init` sets every field" is checked on every path: an `if` counts only when every branch including an `else` sets it, a field set only inside a loop does not count, and a `return` before all fields are set is an error | D12x says the compiler checks; the exact rules (paths, branches, reads before setting) are open |
| P17 | A subclass may not redeclare a parent's field name | open (D12u interaction) |
| P18 | Every other undecided combination (override with `@add`, more than one `@add`, `@add` on other operators, calling a variable, chained comparisons) stops with `not yet decided` | no guess made |
| P19 | The interpreter is partly static: declarations, interface conformance, override and `@init` rules are checked before the program runs. Expression types are checked as the program runs, except that a method or field must exist on the receiver's declared type, found from variables, parameters, function and method return types, and field types (so `make().extra()` is rejected when `make` returns an interface without `extra`). Other expression types, such as indexing, are known only at run time | D04a wants all of it before running; a full static checker is later work |
| P20 | Error wording is the prototype's own | error wording is undecided throughout |
| P21 | A top-level `@name` before a function makes it an entry point; `@main` is the default. An entry point returns nothing; two with one name stop as not decided | D16a settles the idea; the arguments are D28a |
| P22 | Operators on clearly different kinds (a number with a str, bool or class instance) are type errors; mixed number kinds (int with float or rational) and same-type operations without a rule (str + str, float + float) stop as not decided | D04a rejects known mismatches; which conversions exist is open |
| P23 | `range(stop)`, `range(start, stop)` and `range(start, stop, step)` of integers, built in rather than a real library class; the loop variable is an ordinary `int` local that stays after the loop. A `for` over anything else stops as not decided | D18a says range is an ordinary class, but classes and iteration are not designed yet |
| P24 | Text operations: `+` joins, `len(s)`, `s[i]` (a one-character str), `s[a:b]`, `x in s`, ordering by code point, `str(x)`, `int('42')`, and methods `upper lower strip startswith endswith find replace` | D17b-c settle encoding and units only |
| P25 | Strictness: negative indexes, out-of-range indexes and slices (no clamping), empty-pattern `replace`, `str()` of classes and splitting on an empty string are errors or stop as not decided; strings cannot be changed in place | no Python looseness is inherited without a decision |
| P26 | Calls nested more than 10,000 deep stop with an error; the command line runs on a large-stack thread, the browser playground allows fewer | the language has no recursion-limit decision |
| P27 | Lists (D20a): items convert to the element type like arguments do; an empty `[]` needs a declared type; `list[T]` types must match exactly (no `list[int[length=8]]` from `list[int]`); `append`, `len`, indexing, index assignment, `for`, `in`, `split` and `join`. A `for` over a list sees items appended during the loop. Printing shows `[1, 2]` and `['a']`. Equality, `+`, slicing, negative indexes and other methods stop as not decided | D20a settles only the basics |
| P28 | Dicts and sets (D20b, D20c): `dict[K, V]` and `set[T]`; literals `{k: v}` and `{a, b}`; an empty `{}` needs a declared type (`m: map[str, int] = {}` or `s: set[int] = {}`). Keys and set elements may be integers, `str` or `bool`. Order is insertion order. A loop over a dict walks its keys, and over a set its elements, on a snapshot. Methods: dict `keys values remove`, set `add remove`; `m[k]`, `m[k] = v`, `len`, `in`. A missing key or element is a catchable error. Duplicate keys in a literal are an error. Equality stops as not decided | D20b settles only that they exist |
| P29 | Errors (D22a): `try:` ... `catch ClassName as name:` ... `else:` ... `finally:`; `raise value`. Errors are ordinary classes: `Error` has a `message: str` field, `RuntimeError` is raised by failures such as division by zero, an index or key out of range, bad text for `int()`, and a fixed-width overflow, and `IOError` by file failures. Catch clauses are tried in order and match subclasses. Type errors and literal-out-of-range errors are not catchable (they are compile errors in the language). An uncaught error stops the program | D22a settles the keywords only |
| P30 | `None` (D23a) and optionals (D23b): `None` has type `None`; an optional is written `T | None` (only that union is decided) and holds a `T` or `None`. A `None` literal where a non-optional type is expected is a type error; an optional that turns out to be `None` where a plain value is needed (an argument, a member, an operator) fails with a catchable error, since narrowing is not designed. `x == None`, `x != None`, `x is None`, `x is not None` and `x in None` (true when x is None, D23e) work; `is` with other operands stops as not decided. A variable copied from an optional stays optional | D23a-c settle that None, `T | None` and the `is` tests exist |
| P31 | Modules (D24a, D24b, D24c): one file per module, `export` before `def`, `class` or `interface`, and `from module import a, b` (the plain `import module` form is not implemented). Files are found next to the program, on a search path, or in the standard library folder `tomato/std/`. Each module has its own namespace: two modules may declare the same name, the program may reuse a name a module keeps private, and importing two different things under one name is an error. The built-in names (`Error`, `RuntimeError`, `IOError`) are reserved. The standard library today is `math` (abs, min, max, gcd, pow) plus the always-available `builtin` prelude. An imported class prints as its plain name | D24a-c settle that import, export, a standard library and separate namespaces exist |
| P32 | Files (D26a): `open(path)` or `open(path, 'r'|'w'|'a')` returns a `File` with `read()`, `write(text)` and `close()`, in UTF-8; a failure is a catchable `IOError` | D26a settles only that opening files exists |
| P33 | LLVM (D27a, D27b): `!name(a: T) -> R` at the top level declares an LLVM function's Tomato types; `!name(args)` calls it, type-checked like any call. With `--llvm file.ll` the interpreter runs the function through llvmlite's JIT and checks the IR's signature against the declaration; `tomato build ... --llvm file.ll` links the IR in. `int` maps to `i64`, `int[length=N]`/`uint[length=N]` up to 64 bits to `iN` (LLVM has no signs: two's complement), `float` to `double`, `bool` to `i1`, no arrow to `void`. The browser playground has no llvmlite, so `!x` stops there | D27a settles that `!x` names an LLVM function; D27b is my design |
| P34 | Inputs (D28a): each input text is read by its parameter's type: `int` and `uint[length=N]` as whole numbers (range-checked), `float` as a finite number, `bool` as `true`/`false`/`True`/`False`, `str` as is. Other parameter types, and the wrong number of inputs, are errors | D28a settles only the command-line shape |
| P35 | `tomato bundle FILE [-o OUT]` checks the program and writes one executable that bundles the program, the modules it imports, any `--llvm` IR and the Python interpreter; run it as `./OUT [ENTRY [INPUTS...]]`. It is not native code, and the prototype does no reference counting (Python manages memory). `./install.sh` copies Tomato to `~/.tomato` and links `~/.local/bin/tomato` | the real compile target is an open question (72) |
| P36 | The compiler (D30a, D36a) handles `int` (64-bit with an overflow stop, until D32a's automatic size exists), `int[length=N]` and `uint[length=N]` up to 64 bits as LLVM's own N-bit integers with overflow stops, `float` (from `/`, comparisons and printing only), `bool`, strings, `list[T]`, `dict[K, V]`, `set[T]`, classes (including `@add`, conversions and `override`), interfaces, errors, functions, recursion, `if`/`while`/`for` (over `range`, lists, dicts and sets), `break`/`continue`, `print`, and an entry point whose inputs come from the command line. Not compiled yet: optional `int`, `float` and `bool`, imported modules, string methods other than `+`, `len`, indexing, slicing, `in`, comparison and `str()`, list slicing, `in` on lists, printing lists, dicts or objects, and equality of lists, dicts or sets. Out-of-range indexes, including negative ones, are run-time errors (the interpreter stops negative ones as not decided). The IR uses opaque pointers, so it needs LLVM 15 or newer, and links with `tomato/runtime/tomato_rt.c` | D30a settles only that the output is LLVM IR |
| P37 | Error modes (D34a): `--mode debug|normal|release` on `compile` and `build`, debug by default. Debug prints `error: line N: message`, normal prints `error E<kind>:<line>` (for example `E02:2`), release prints nothing; all exit with status 1. `tomato explain CODE FILE` decodes a code against the source. The interpreter always prints full messages | D34a settles the three modes and decoding with the source, not the formats |
| P38 | Cycle notices (D29b): after loading, the interpreter, compiler and bundler print a note on standard error when two or more classes refer to each other through their fields (including inherited fields, `list`, `set` and `dict` element types, and interface-typed fields, which point at every implementer). It says compiled programs free such cycles with the cycle collector. A class referring only to itself is not reported. Notes do not stop the program | D29b settles only that some detection exists |
| P39 | Allocation (D36a): every heap object starts with a header {reference count, type code} (D35a); the type code indexes generated destructor and vtable tables. A negative count marks an immortal static object (string literals). Every expression of a heap type yields a reference the caller owns; locals, including parameters, own their value and are released in one epilogue that all returns pass through. Dot calls are direct unless the class has subclasses, then they go through the vtable. Strings are UTF-8 with a byte and character length, indexed by a linear scan (D17c's chunked index is later work). In debug mode the program reports objects never freed at exit (D29c), after a final cycle collection; normal and release modes do not. Plain pointers are used instead of D35a's 128-bit value pair | D36a settles that the compiler allocates by reference counting |
| P40 | Errors in compiled code (D22a): a pending error object lives in a global that every call checks; `raise` and the language's own run-time failures (division or modulo by zero, integer overflow or out-of-range conversion, an index, key or element that is missing, a duplicate dict-literal key, a failed class conversion) set it and jump to the nearest `catch`, else the function returns early and its caller checks. Run-time failures are `RuntimeError` objects whose message is in the error mode's form (debug: `line N: text`, normal: `E02:5`, release: empty), so a program that prints one sees different words than the interpreter. `finally` blocks are copied onto each exit: normal, caught, propagating, and `return`/`break`/`continue`. An uncaught error stops the program in the current error mode (debug `error: line N: uncaught error Class: message`, normal `error E11:N`). After any error has been raised the debug leak check stays quiet, since temporaries held mid-expression can be dropped. A catch variable reused with another class gets a new slot | D22a settles only that errors exist |
| P41 | Dicts and sets in compiled code (D20b, D20c): an insertion-ordered hash table in the runtime with integer, bool and string keys and values of any type. A loop over one walks a snapshot of its keys, like the interpreter. A missing key, or removing one that is not there, raises a catchable error; `in` compares integer keys by value. A reference cycle through a dict is freed by the cycle collector (P42) |
| P42 | Cycle collector (D29d): a synchronous trial-deletion collector in the C runtime. A heap object whose count drops but stays above 0 becomes a possible root; the collector runs when 10,000 roots have piled up, and once more at exit in debug mode. It traces objects by the generated kind and offset tables, with explicit stacks so deep chains and long rings do not overflow the C stack, and frees whatever has no reference from outside the traced graph. `TOMATO_GC_STATS=1` prints the running total of objects freed in cycles. The collector flags live in the upper bits of an object's type word, so compiled code masks the type code. Strings are never roots. It is not safe with threads yet (D31a) | D29d settles only that cycles are freed automatically |
| P43 | Default arguments (D19c): `name: T = value` after the type; defaulted parameters must come last; a default is evaluated at each call, in the callee's module, and cannot see the caller's variables; entry-point inputs may be left out when defaults exist in the interpreter (compiled entry points need every input). Optionals in compiled code: `T | None` is a nullable pointer for heap types (str, list, dict, set, objects, interfaces); optional `int`, `float` and `bool` are not compiled yet; using an optional where a value is needed raises a `RuntimeError` (code E12) when it is None; ordering comparisons of optionals are not compiled | D19c settles that defaults exist |
| P44 | `x in Type` (D23f) tests the value's type: a class name matches subclasses, an interface name matches implementing classes, `int` matches only plain `int` (not fixed-width ints or `bool`), and an optional is tested by its current contents. Only bare type names work on the right; `list[int]`, `int[length=8]` and unions are not decided. The compiler stops on interface tests it can't decide statically | D23f settles that `x in Type` is the type check |
| P45 | Unions (D23g): `A | B | ...` of any types, in any order; `T | None` stays the optional of P30. Assigning checks the members in order and takes the first that accepts the value; member access and operators on a union value are checked when the code runs (no narrowing). Interpreter only: the compiler still handles just `T | None` on heap types | D23g says `|` is an operator on types |
| P46 | Operators (D23h): `&` between types is an intersection of interfaces and at most one class (at least one member must be an interface), checked as every member; `&`, `|`, `^` between whole numbers are bitwise and/or/xor with Python's precedence, the result in the wider operand's type; `xor` joins `not`/`and`/`or` as a bool-only operator that evaluates both sides. `|` and `&` mean union and intersection between types and bitwise operations between values. Interpreter only, except `xor` | D23h settles that these operators exist |
| P47 | Self-hosting (D38a): `selfhost/` holds the compiler written in Tomato, run by the interpreter until the Python compiler can build it. The lexer drops the Python one's `\u{...}` escapes and uses a bracket-depth counter and an explicit indent stack (lists only support `append` so far) | D38a says the next compiler is written in Tomato |
| P53 | The compiler in Tomato (`selfhost/compiler.tom`, D38a), so far int, bool, str and `list[int|bool|str]` programs: functions, locals, + - * % and comparisons, text + == != < <= > >=, indexing, slicing, `len`, `str`, list literals, `append`, item assignment, `for x in list`, classes (fields with defaults, `@init`, methods, construction, field read and write, `list[Class]`; no inheritance or interfaces yet), text methods find/replace/split/join/startswith/endswith, `in` on text and lists of int/bool/str, files (`open`, `read`, `write`, `close`), and/or/xor/not, if, while, `for ... in range`, break, continue, calls, print. Values carry their types, text is reference counted like the Python compiler (owned temporaries, slots release what they held, an epilogue releases slots), and the IR links with the C runtime. Numbers are 64-bit and wrap on overflow, a zero `%` divisor is not checked, `and`/`or` evaluate both sides, and text literals must be ASCII. Anything else stops with a CompileError. `not in` is not valid Tomato, so the sources write `not (x in y)` | D38a needs a compiler written in Tomato; this is its growing slice |
| P52 | The Tomato parser (`selfhost/parser.tom`, D38a): every syntax node is one `Node` class (kind, line, an ordered list of tagged `Val` fields in the Python `nodes.py` order), because compiled code has no unions or tuples yet. Declarations inside loops are not decided, so loop bodies get fresh lists from small helper functions. `str.join` is compiled (C runtime, bootstrap) | D38a needs the parser to build with the Python compiler |
| P51 | Imported modules in compiled code (D24, D38a): functions and classes from `from m import ...` and the standard library compile into the one program, each keeping its module-qualified name (so two modules may both define `Item` or `helper`). Names resolve in the module where the code was written. `examples/features.tom` now builds with the same output as the interpreter | The Tomato compiler will be several modules |
| P50 | Compiled files and text methods (D38a): `open(path[, mode])`, `read()`, `write(text)` and `close()` on a `File` that the program closes itself (a missing file raises a RuntimeError, error code 13, not IOError); text methods `find`, `replace`, `split`, `startswith` and `endswith` (an empty text to replace or split on stops with error code 14). Written in the C runtime as bootstrap work | D38a needs the Tomato lexer to build with the Python compiler |
| P49 | `x in list` in compiled code walks the items comparing each with `==` (items of any type `==` supports); the selfhost lexer now compiles up to its file-reading entry | D38a needs the lexer to build with the Python compiler |
| P48 | `tuple[T]` and variadic parameters (D39a): a tuple is an immutable list of one item type (no literal; made by `*args`); `*args: tuple[T]` and `**kwargs: dict[str, V]` need a type, no default, and come last in that order. Keyword arguments work only for functions, methods and classes you define, and a keyword argument cannot be followed by a positional one. Entry points read extra inputs and `name=value` inputs with the D28b rule; an input like `a=b` is treated as a keyword only when the entry has a parameter named `a` or a `**kwargs`. Interpreter only | D39a settles that `*args` and `**kwargs` exist and use tuple and dict |

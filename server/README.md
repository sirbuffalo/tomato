# Compile server

`python3 server/compile_server.py [--port 49212]` serves `server/compile.html`: type a Tomato program, press "Compile and run", and the server compiles it with the compiler written in Tomato (built by itself on first start into `build/`), links it with clang and runs it with a 5 second limit. It runs code on the machine, so it binds to 127.0.0.1 only. Programs run under `sandbox-exec` (macOS): they can write only inside their own temporary directory and cannot read anything under /Users, /Volumes, /tmp, /private/var/tmp or the per-user temp directory (everything else, such as /etc, /opt and /Library, stays readable), have no network and cannot fork, but they can still read system files such as /etc, use CPU for 5 seconds and up to 1 GB of memory (polled). The compiler and clang steps run unsandboxed as the server user (they need the repo and toolchain), so a compiler bug is not contained. The server refuses to run programs where `sandbox-exec` is missing. Requests need `Content-Type: application/json` and a local or `*.ts.net` Host (`--allow-host` adds more); anyone who can reach the port can still run sandboxed code, so this is a best-effort sandbox (exec, IPC and any libc function stay allowed), not a security boundary: start it only when needed and only on a tailnet you trust.

The website in `site/` calls this server for its Run and Repl page: start it with `--allow-origin https://tomato.davismcd.com` and set its public URL in `site/config.js`.

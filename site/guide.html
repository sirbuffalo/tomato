Guide

A tour of the language as it runs today. Every example runs on this site's Run page. The reference lists every decision behind these rules.

Programs

A program starts at a function marked @main. The examples below show bare statements, which this site's Run page and repl wrap in an @main for you. Functions also take other entry names, such as @prime; tomato run FILE prime 17 runs it with the input 17, read as the most restrictive type its parameter allows.

def greet(name: str, times: int = 2) -> str:
    out = ""
    for i in range(times):
        out = out + "hi " + name + "; "
    return out

print(greet("tom"), 10 / 4, 7 % 3)

Types

  • int is 64-bit for now and stops on overflow (the design is unlimited growth, not built yet). int[length=8] and uint[length=8] have a fixed width, stop on overflow, and need an explicit conversion from int: uint[length=8](x).
  • float is a 64-bit IEEE double; / between whole numbers gives a float (10 / 4 is 2.5). Float literals, // and ** are coming back to this compiler.
  • rational is exact: rational(1, 3). bool, str, list[T], dict[str, V], set[T], and T | None for optional values.
  • Types are checked at compile time. A constant out of range for a fixed-width type, like uint[length=8] = 300, is a compile error.

Classes and interfaces

interface Shape:
    def area(self) -> int

class Rect implements Shape:
    w: int
    h: int
    @init
    def make(self, w: int, h: int):
        self.w = w
        self.h = h
    def area(self) -> int:
        return self.w * self.h

shapes: list[Shape] = [Rect(2, 3), Rect(4, 5)]
total = 0
for s in shapes:
    total = total + s.area()
print(total)

Single inheritance with override, private and const fields, and interfaces with dynamic dispatch. Memory is reference counted and the runtime frees cycles.

Errors

try:
    v = int("x")
catch RuntimeError as e:
    print("caught", e.message)
n: uint[length=8] = 250
print(n + 5)

Runtime failures (overflow, division by zero, a bad index) raise a catchable RuntimeError; a missing file raises IOError. Type errors are never catchable.

Modules and LLVM

from util import f imports a module's exported names. !name(a: T) -> R declares a function from LLVM IR you supply with --llvm, and !name(x) calls it.

Commands

tomato run FILE [ENTRY [INPUTS…]]compile, link and run
tomato build FILE [-o OUT]write a native program
tomato compile FILEprint the LLVM IR
tomato repl [FILE…]interactive prompt with history (arrow keys) and +=; needs only the compiler and clang; each line joins the session, which is compiled and run, and only new output is shown; :program, :save, :compile. Because the whole session re-runs on each line, a side effect outside the program (writing a file) repeats, and a function or class you define cannot read your variables (pass them as arguments)
tomato updateinstall the newest release
tomato versionprint the version

Not yet

The compiler written in Tomato does not yet have float literals, //, **, mixed int/float arithmetic, top-level code (the Run page and repl wrap it in @main), the pre-run static check, tuples, *args/**kwargs, keyword arguments or unions. They were prototyped in an earlier Python implementation that has been retired; see open questions.

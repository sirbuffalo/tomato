macOS installer

Double-click the package and follow the steps. It installs to /usr/local/lib/tomato and links /usr/local/bin/tomato, with prebuilt compilers for Apple silicon and Intel, so nothing is built at install time. Programs are still compiled with clang, so you need the command line tools.

The package is signed and notarized by Apple, so macOS opens it on a plain double-click. You can also run sudo installer -pkg tomato-VERSION.pkg -target /. To check the download, compare shasum -a 256 tomato-VERSION.pkg with the SHA-256 above. tomato update works on a package install too. The installer hands /usr/local/lib/tomato to the user who installs it, so update needs no sudo; the flip side is that any process running as that user can change the command, which is the same trust as the ~/.tomato install. On a shared Mac, run sudo chown -R root /usr/local/lib/tomato and update with sudo instead. To uninstall: sudo rm -rf /usr/local/lib/tomato /usr/local/bin/tomato, then sudo pkgutil --forget com.davismcd.tomato.

Install from the tarball

tar -xzf tomato-VERSION.tar.gz
cd tomato-VERSION
./install-native.sh
tomato version

This builds the compiler from the checked-in IR into ~/.tomato/native and links ~/.local/bin/tomato. Put ~/.local/bin on your PATH. An existing tomato that is not ours is kept as tomato.old.

Update

tomato update

Reads latest.json, checks the download against its SHA-256, and reinstalls when a newer version exists.

Trust

tomato update trusts HTTPS and the manifest: it reads the version, download URL and SHA-256 from one file, requires an official github.com/sirbuffalo/tomato/releases URL and a valid checksum, and only ever upgrades. Archives are not separately signed yet, so anyone who can change latest.json on the site or the main branch can change what gets installed.

Method

  • Same work. Each language implements the same loop-for-loop algorithm (no tricks such as caching that only one language could use) and prints a checksum. benchmarks/run.sh fails the run if any version prints something different from the Tomato version.
  • Builds. Every number below used the command shown here. Tomato is built by this repository's own compiler twice: in release mode (no leak checks, short error codes) and in debug mode (leak checks and full error text), and each is shown separately. Go and Rust use their usual optimized builds, and Python is the CPython interpreter as installed.
    • Runs. Each program runs 10 times (Python too). The runs of every benchmark and language are shuffled into one random order with a fixed, recorded seed, rather than run back to back, so thermal throttling and background load fall evenly on every row. The table shows the median, the fastest run and the spread (slowest minus fastest, over the median); every time is in benchmarks.json. Time is the wall clock of the whole process (including start-up, which is a few milliseconds), and memory is the peak resident size.
    • Not tuned. The programs are written the way a beginner in each language would write them: lists, strings and dicts from the standard library, objects as separate heap allocations (a Box in Rust, a pointer in Go). Nobody hand-tuned any version.

    Caveats

    • One machine, one run of the suite, fixed inputs. About half of the timings varied by more than 20% between the fastest and slowest run. Other programs ran on the machine at the same time (the load average is at the top of the page), so small differences are noise; the spread between the fastest and slowest run is in the JSON.
    • Tomato is young and its compiler does little optimization of its own (release mode relies on clang and link-time inlining of the runtime). The numbers are a snapshot of this version, not a verdict on the language.
    • Tomato's int is unlimited in size, with small values held in one tagged word; Go, Rust and (for big values) Python pay different costs for numbers, so the integer benchmarks compare designs as much as compilers. The Go int and Rust u64 versions can overflow silently or stop; the checksums are chosen not to.
    • The sort benchmark compares different algorithms: Tomato's sorted is an introsort (quicksort that falls back to heapsort, with insertion sort for short runs) for lists of ints, floats and strings, Rust uses the standard library's sort (a stable merge sort), and Go its sort package. A Rust radix sort (benchmarks/sort/sort_radix.rs) is measured too and shown under the sort chart, because a radix sort is what the fastest sort for small ints looks like.
    • Every language uses its usual fast library for big integers: math/big in Go, the built-in int in Python, and the num-bigint crate in Rust (whose standard library has none), built with cargo build --release; benchmarks/bigint/Cargo.lock pins the crate versions. Tomato uses its own built-in int.
    • The mandelbrot checks use explicit float conversions in Go so that no fused multiply-add changes a result.
    • Rust and Go may inline or remove work a language without a heavy optimizer cannot; the checksums prevent removing it entirely, but loops can still be unrolled and vectorized.

    What the numbers suggest for Tomato

    The list is in docs/performance.md.

    1. Add function values and a stable merge sort for compare and key functions; sort is slower than Rust's standard sort.
    2. Compile range(a, b, step) loops to counted loops (sieve).

    Since v0.48 release mode links the program and the runtime with link-time optimisation and the cycle collector skips objects that cannot form cycles; since v0.49 the compiler no longer counts references for reads of a variable that keeps its value alive.

    Source

    Everything is in the benchmarks/ folder: one folder per benchmark with its four programs, sizes.txt (the inputs), run.sh (the runner), measure.c (the timing helper) and results/ (the numbers on this page). Run benchmarks/run.sh yourself; it needs clang, go, rustc and python3 and skips any that is missing. The Python programs exist only as a comparison; Tomato's own tooling uses no Python.
